# AGENTS.md — vibe-chat

Корпоративный мессенджер (self-hosted): личные/групповые чаты, боты с собственным API, файлы и фото, в перспективе mini-apps, звонки, мобильные приложения. Продуктовая и архитектурная правда — в `Docs/concept.md`; при противоречиях с этим файлом приоритет у концепции.

## Статус

MVP **полностью реализован** (13 этапов дорожной карты) + **звонки A/B/C и файловый флоу — реализованы и проверены на стенде** (2026-11-19, merch-vibe.ru): бэкенд — auth, чаты, сообщения+файлы (upload → presigned PUT в Silo → complete со sniffing/thumbnail/blurhash), realtime, cleanup, боты, каркас mini-apps, реакции (137 тестов); фронтенд — логин Keycloak, открытая регистрация (env `APP_OPEN_REGISTRATION`, автовход ROPC), чаты, лента (вложения: сетка картинок + список файлов, лайтбокс с навигацией по всем фото чата; реакции, цитирование, пересылка), realtime, профиль, админ-секция инвайтов (vitest 14). Звонки: аудио 1:1 (ringing), групповые (join-модель), видео (полноэкранные плитки, шаринг экрана) — LiveKit. Инфраструктура: скрипт бэкапов PostgreSQL+Silo+конфигов (`deploy/backup.ps1`; ограничение — KC-учётки на встроенном H2 не бэкапятся), `JAVA_OPTS_APPEND` для KC (heap по умолчанию 256–512 МБ, переопределение через `KC_JAVA_OPTS_APPEND` в server.env). Следующий кандидат: coturn (нужен DNS turn.* + TLS; без него звонки работают везде, кроме симметричных NAT). Мобильный клиент (Android) — **этапы 1–5 реализованы и проверены e2e на эмуляторе** (этапы 1–2 — 2026-11-19, этапы 3–5 — 2026-11-20; решения и подводные камни в `Docs/android.md` §9, adb-приёмы в `mobile/README.md`): auth (ROPC + PKCE-fallback), чаты/сообщения с оффлайн-кэшем (MMKV), realtime (WS-доставка < 1 c, typing, presence-heartbeat на бэкенде, реконнект с догонянием `updated_after`), вложения (Photo Picker → presigned PUT в Silo → complete, прогресс/отмена, thumbnail/blurhash в ленте, лимит 100 МБ до PUT, медиа-кэш переживает перезапуск). Критические фиксы по ходу e2e: WS-реконнект не плодит соединения (guard `socket !== ws`); клиент разворачивает обёртку `{message: …}` в WS `message.*`; optimistic-отправка мержится по `client_ref` = Idempotency-Key (один ключ в onMutate и mutationFn); размер upload берётся из `blob.size` (`asset.fileSize` пикера врёт → 403 подписи), Content-Type не подписывается; лимит файла проверяется до fetch (fetch >100 МБ content:// в RN падает). Подводный камень PKCE в dev: весь флоу должен ходить на **одном** хосте KC — в `mobile/.env` `EXPO_PUBLIC_KC_URL=http://localhost:8080` + `adb reverse tcp:8080` (разные хосты формы и frontendUrl ломают cookies: «Restart login cookie not found»). Токены — react-native-keychain 10.x (Android Keystore), **обязательно `service` в options `setGenericPassword`** (иначе restore не находит токены). KC-настройки для ROPC (без них `invalid_grant: Account is not fully set up` / 401 iss-mismatch): все required actions `enabled=false`, realm `frontendUrl` = issuer, который валидирует бэкенд (`APP_KEYCLOAK_URL`); зафиксировано в `deploy/keycloak/realm-export.json` (плейсхолдер `VIBE_KC_FRONTEND_URL` в compose-env). Комментарии-маркеры `//_section:`/`//_note:` в рантайм-коде mobile запрещены (проектный плагин ломает бандл: "Compiling JS failed"). Dev-KC :8080 (в `mobile/.env` `EXPO_PUBLIC_KC_URL=http://localhost:8080`, работает через `adb reverse tcp:8080`; :8444 — серверный стенд). Этап 1 (каркас: Expo dev build RN 0.79.6, minSdk 33/target 35, expo-router, сервисы config/api-client/ws-client/diagnostics, Zustand session store, env `EXPO_PUBLIC_*`, иконки `mobile/assets/gen-icons.ps1`) — выполнен ранее (2026-11-19). ## Стек (зафиксирован)

- **Backend:** Python 3.12+, FastAPI, SQLAlchemy + Alembic, Pydantic v2
- **Frontend:** React + TypeScript + Vite (только web; мобильные — перспектива, см. `Docs/android.md`); UI — **Tailwind CSS + shadcn/ui**; data layer — **TanStack Query (REST-кэш) + Zustand (WS-состояние)**
- **CI:** нет — локальные проверки (ruff/mypy/pytest, oxlint/tsc/vitest); пересмотреть при появлении второй площадки разработки
- **DB:** PostgreSQL (основное хранилище всего)
- **Кэш/Pub/Sub:** Valkey — не Redis. Никогда не добавлять redis-пакеты/образы
- **Объектное хранилище:** Silo (S3-совместимый, форк MinIO от Pigsty) — не MinIO. В коде и конфигах именование Silo / `SILO_*`; только сам Silo-контейнер может использовать свои исторические `MINIO_*` env-переменные
- **Auth:** Keycloak (OIDC; MVP — логин-пароль, потом LDAP/Kerberos через федерацию). Realm-роли в MVP не используются; авторизация по членству в чатах; в realm-export обязателен audience mapper. Keycloak — **только идентификация/аутентификация** (`sub`); персональные данные (имя, фамилия, почта) — в PostgreSQL системы, из JWT-клеймов не берутся (§5 концепции)
- **Realtime:** WebSocket + Valkey Pub/Sub
- **Звонки (этапы A/B/C, §17 концепции; реализованы):** LiveKit self-hosted (SFU) + coturn (TURN — ещё не деплоен, нужен DNS turn.* + TLS); сигналинг звонка — наш WS, медиа — напрямую в LiveKit по room-токену. Никакого P2P-mesh и Jitsi-iframe.
- **Деплой:** Docker Compose, монорепо `backend/` + `frontend/` + `Docs/` + `deploy/`. Тестовый стенд — `merch-vibe.ru` (VPS): системный nginx (`/chat` → SPA+API+WS, `/vibe-files/` → Silo без срезания префикса, `:8444` → KC); presigned URL подписываются на `SILO_PUBLIC_URL` — scheme://host **без пути** (host и путь входят в подпись S3v4). Frontend: сборка с `VITE_BASE_PATH=/chat/` + `VITE_KC_URL`, dist копируется scp на сервер (bind mount держит inode → `rm -rf dist` + замена + `chmod -R a+rX` + `--force-recreate`).

### Регистрация (инвайт-коды + открытый режим)
- Коды multi-use выдаёт платформенный админ (`max_uses` NULL = безлимит, опциональный срок, деактивация); в БД только sha256-хэш. `POST /auth/register` (без аутентификации): код + username + пароль + персональные данные → последние только в PostgreSQL. KC-аккаунт через Admin API (client `backend-admin`, client_credentials) — только username+password; `registrationAllowed` KC остаётся false. Без `APP_KEYCLOAK_ADMIN_CLIENT_SECRET` — 503 (§5, §12).
- Открытый режим (env `APP_OPEN_REGISTRATION`, default false; на стенде включён): регистрация без инвайт-кода; после регистрации — автовход через ROPC (`signinResourceOwnerCredentials`, direct grants для клиента `frontend` в realm-export) + **полная перезагрузка страницы** (AuthProvider видит ROPC-сессию только при инициализации, SPA-navigate ломал).

## Ключевые архитектурные решения

- Бэкенд не выдаёт токены — только валидирует JWT Keycloak'а (JWKS, iss/aud/exp). Исключения — скоупед токены для внешних подсистем: opaque `mat_…` для mini-apps (Docs/concept.md §11) и room-JWT LiveKit для звонков (TTL ~10 мин, конкретная комната; §17).
- Keycloak — только identification/authentication: из JWT берутся `sub` и `preferred_username` (начальный логин). Персональные данные (`first_name`, `last_name`, `email`, `display_name`, аватар, пояс) живут в PostgreSQL и редактируются через `PATCH /users/me`; из клеймов (`name`, `email` и т.п.) не берутся, с Keycloak не синхронизируются (Docs/concept.md §5).
- `messages.type` только `text|system`; тип медиа живёт исключительно в `attachments.kind` (сверяется с `real_mime_type`, несовпадение — 422). Не добавлять `image/video/file` в `messages.type`. Видео в MVP: метаданные извлекает клиент (ffmpeg на бэкенде нет).
- Файлы не проксируются через бэкенд: presigned PUT/GET напрямую в Silo; URL встраиваются в сериализацию сообщений. У Silo два адреса в конфиге: `SILO_INTERNAL_URL` (серверные операции) и `SILO_PUBLIC_URL` — scheme://host **без пути**, на нём подписывается presigned URL (host и путь входят в подпись S3v4; подпись на internal-endpoint с подменой host'а строкой даёт 403 SignatureDoesNotMatch). Системный nginx отдаёт Silo по `/vibe-files/` (proxy_pass без слэша — путь как есть). Бэкенд генерирует thumbnails (Pillow — по **полному** объекту, не prefix 64 КБ: truncated JPEG не декодируется) и blurhash (**по thumbnail**, не по оригиналу — encode O(w·h), 9 МП ≈ 59 с → 504); real_mime — sniffing, kind вложения на клиенте — по `real_mime` от сервера (HEIC под видом .jpg → file); `thumb_key`/`blurhash` — в `files` (не в `attachments`); SVG — не image. Браузерный PUT в Silo — same-origin через системный nginx в проде; в dev (SPA :5173 → Silo :9000) на Silo обязателен CORS, иначе загрузки падают на preflight.
- Боты: управляет только **платформенный админ** (`users.is_platform_admin`, MVP — seed-пользователь); в чаты ботов добавляют чат-админы; в Bot API есть чтение истории (`/bot/chats/{id}/messages`) — без него resync бота невозможен.
- `messages.id` — UUIDv7 (пагинация и сортировка по id), главный индекс `(chat_id, id)`; `updated_at` — курсор догоняния edit/delete при реконнекте (`?updated_after=`); идемпотентность отправки через `Idempotency-Key`/`client_ref` (UNIQUE sender+client_ref+chat_id). Все времена в БД/API — UTC (`timestamptz`, ISO 8601 `Z`); время сообщения передаёт только сервер.
- Часовые пояса: `messages.timezone` — эффективный пояс отправителя в момент отправки (клиент передаёт, сервер валидирует по IANA, иначе NULL; у ботов/system — NULL); режим отображения — `users.time_display` (`browser`|`as_sent`|`fixed`|`utc`).
- Сообщения удаляются soft delete; пересылка — только через `POST /messages/{id}/forward` (в обычной отправке forward-поля не принимаются), вложения при пересылке копируются, снапшот автора — в `forward_snapshot`; системные сообщения (`type=system`) нельзя цитировать/пересылать/редактировать. Чат удаляется soft delete (`chats.deleted_at`, в списках не показывается).
- Realtime: fanout через Valkey Pub/Sub; события ботов — Valkey Streams (long polling `/bot/updates`, offset = Stream ID, retention 24 ч, `resync: true` при отставании). Presence — счётчик соединений в Valkey (не в процессе бэкенда), `users.last_seen_at` пишется при обнулении счётчика.
- WS auth через одноразовые tickets (`/ws/ticket`, атомарное удаление GETDEL), не через токен в query. Истечение JWT в живом WS — норма, соединение не пере-валидируется. Client→server по WS — только `typing`; все мутации через REST. Несколько одновременных WS-соединений на пользователя допустимы (вкладки/устройства), каждое со своим ticket.
- Mini-apps: в MVP только каркас — поля в БД + два эндпоинта (one-time код → mat_-токен), контракт `postMessage` в концепции (§11). UI не строить.
- Реакции: только фиксированный набор эмодзи (`thumbs_up`, `heart`, `laugh`, `fire`, `check`), toggle-API `PUT /messages/{id}/reactions`, составной PK (message_id, user_id) — одна реакция на пользователя; не двигают `updated_at` сообщения (§6). Ботам реакции не доставляются (только message.*, §10).
- Масштаб MVP: до ~1k пользователей; вертикальные обновления, а не миграция на очереди/микросервисы.
